# Grafana MCP runtime image

This image contains the official Grafana MCP server `v2.0.0` and OpenAI tunnel-client runtime `v0.0.15`. The Dockerfile selects the official Linux `x86_64` or `arm64` release archive, verifies its SHA-256 digest, extracts only `mcp-grafana` and `tunnel-client`, and runs both as UID/GID `65532` with a read-only root filesystem in Kubernetes. The image does not contain a Grafana URL, service-account token, tunnel identity, or Control Plane key.

The verified archive digests are `mcp-grafana_Linux_x86_64.tar.gz` `0a0dde2c882c24fedcce79a07d97b232f71730c744b84a09b6b0735c2ca3d024`, `mcp-grafana_Linux_arm64.tar.gz` `5b29581cad5ce21a0db67c655e5e7e71a9163b4e1ba1b518559baa3c54133a28`, `tunnel-client-runtime-v0.0.15-linux-amd64.zip` `f26f8b3ee6c335e38fa5cfbe6ce5635f53738f08a26eecf07d6cebacab4a1abf`, and `tunnel-client-runtime-v0.0.15-linux-arm64.zip` `a868d295385b22449341fa141b911f3e991583e45b1fa2a5bfb946aed1861b88`.

The runtime contract is:

| Setting | Source and default | Purpose |
| --- | --- | --- |
| `CONTROL_PLANE_API_KEY` | Secret `mcp-grafana-credentials`, required | Runtime tunnel key with Control Plane Read and Use permissions. |
| `CONTROL_PLANE_TUNNEL_ID` | ConfigMap `mcp-grafana-config` key `control-plane-tunnel-id`, staged as `activation-required` | One tunnel identity for the Grafana integration. |
| `GRAFANA_URL` | Deployment value `https://grafana.bohdal.name` | Canonical HTTPS Grafana origin. |
| `GRAFANA_SERVICE_ACCOUNT_TOKEN` | Secret `mcp-grafana-credentials`, required | Dedicated Grafana Viewer identity; never write or admin. |
| `MCP_GRAFANA_METRICS_DATASOURCE_UID` | ConfigMap `mcp-grafana-config` key `metrics-datasource-uid`, set to `VictoriaMetrics` | Startup guard allowlist for Prometheus query and discovery bindings; must match the chart-proven metrics UID. |
| `MCP_GRAFANA_LOGS_DATASOURCE_UID` | ConfigMap `mcp-grafana-config` key `logs-datasource-uid`, set to `VictoriaLogs` | Startup guard allowlist for Loki query and discovery bindings; must match the chart-proven logs UID. |
| `DO_NOT_TRACK` | Deployment value `1` | Disables runtime usage telemetry. |

The declarative command also disables usage telemetry with `--usage-stats=disabled`. The command enables only search, Prometheus, Loki, alerting, dashboard, folder, and navigation categories and disables write, generic datasource, raw API, SQL, admin, proxied, and run-panel-query tools. A standard-library stdio guard around the unchanged official binary checks the fixed 23-tool read-only catalog and rejects unknown tools and missing, nested, aliased, duplicate or conflicting datasource bindings before dispatch. Prometheus query and discovery tools require `datasourceUid=VictoriaMetrics`; Loki tools require `datasourceUid=VictoriaLogs`. Generic datasource metadata and all-datasource health tools are absent. Dashboard and alert payloads may still mention excluded datasource names; these references do not grant backend access. The guard discards child stderr and passes only the Grafana environment, without tunnel credentials. VictoriaLogs uses the supported Loki tools with a 100-entry log limit and 15-second Grafana timeout; callers should narrow selectors and time ranges. The relay bounds each output frame to 4MiB, which is a protocol ceiling, not a universal query-result budget. Existing Grafana metrics and SNMP dashboards remain the NAS diagnostics path.

Kubernetes starts `/usr/local/bin/tunnel-client` as PID 1 with one stdio Grafana child, one concurrent request, in-memory runtime state, and no Service, ingress, PVC, or VIP. Cilium permits DNS, the OpenAI control plane, the Grafana HTTPS VIP, and the translated metrics Grafana pod backend only. The Grafana tunnel identity must be associated with both Codex and ChatGPT in the intended organization/workspace. Account-level tunnel creation and association use the separately authorized OpenAI Platform management surface; the runtime key itself is limited to Read and Use, and account rights or client bindings are not verified by this image.

Builds must be performed by the trusted image workflow from `main`, which publishes multi-architecture images with provenance and SBOM and reports a digest. Review that digest, commit it to the Flux Deployment, bootstrap the Secret key metadata through the approved Bitwarden operator contract, and verify the Viewer/token and tunnel preflights before unsuspending the child. The current child stays suspended with zero replicas and `activation-required` references; unsuspending with zero replicas is the namespace/policy phase, and setting one replica requires a separate production approval. The repository does not automate account or Secret creation and must not log credentials or raw Grafana responses.

For a credential-free local check, run `mise run mcp-container-build` and then `mise run mcp-grafana-check` as separate invocations in the repository devcontainer. A live preflight additionally needs a valid canonical Grafana certificate, ready metrics and Cilium/DNS paths, Secret key-name metadata, an immutable image digest, and an actual tunnel ID, but it still does not prove effective Viewer permissions, fresh RouterOS/return-path evidence, or both client bindings.
